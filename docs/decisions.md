### Hold every core command to its window's folder

- **Date:** 2026-11-18
- **Change:** A core command sent without a folder used whichever folder was natively open. The bridge now adds the folder this window shows to every such call, and the existing native check refuses it when another folder is open, so the rule covers every feature and reads as well as writes; calls that captured their folder before waiting keep sending that one, and a window with no folder open sends none. History and trash lists show that refusal instead of an empty list. Creating a folder from the sidebar, a team invitation "in its own folder", a team brought to this computer and first-run setup used to open the new folder before this window saved; they now find the folder first, save notes and keep the assistant's reply through the existing folder-switch path, and only then create and open it.
- **Why:** Devin Review on #602 reported both problems. Reproduced in the real macOS app on `fb92c6e`: with window 1 kept on folder A by a permission-denied unsaved edit while a second window opened B, eleven workspace operations wrote under B; a fresh review of the first fix reproduced the same through database cells, customers, profiles, plugin data, settings, a Noticed watch and Share chat (A's conversation text written into B), counting 40 core calls without a folder, 17 of them writers. Creating a workspace during a streaming reply (loopback stand-in provider) lost the partial reply because its transcript save for A was refused once the new folder was serving, while an ordinary switch kept it; the reviewer reproduced the same order in team invitations and setup.
- **Decided by:** Devin, on that native evidence within Pratham's 2026-11-16 reliable task/sync mandate ("can u make it proper and reliable for windows and linux with sync and every feature properly made and tested") and the bounded assignment to close the class at the one existing boundary and reuse the existing flush, with no new store, queue or manager.
- **PR:** [#605](https://github.com/lokus-ai/lokus/pull/605), into `next`.
- **Reversal:** Revert this PR; no file format or storage migration changes.

### Connections belong to a workspace

- **Date:** 2026-11-18
